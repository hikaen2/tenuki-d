## Purpose

floodgate の棋譜から、Bonanza メソッドで pp.bin を学習する。学習用棋譜の作成、学習の手順、学習結果の pp.bin が満たす性質を定める。

## ADDED Requirements

### Requirement: 学習用棋譜の作成
棋譜変換スクリプトは、floodgate の CSA 棋譜ファイル群から、次の条件をすべて満たす対局だけを選ばなければならない (SHALL)。
- 平手の初期局面から始まる
- 先手と後手のレーティングが、どちらも指定した値以上である
- 投了（%TORYO）で終わっている

選んだ対局は、1行に1局ずつ、CSA 形式の指し手（`+7776FU` など）を空白区切りで並べたテキストとして出力する。

#### Scenario: レーティングで選ぶ
- **WHEN** 最低レーティングを 3000 にして、先手 3100・後手 2900 の対局を含む棋譜群を変換する
- **THEN** その対局は出力されない

#### Scenario: 駒落ちを除く
- **WHEN** 駒落ちの初期局面から始まる対局を含む棋譜群を変換する
- **THEN** その対局は出力されない

#### Scenario: 出力形式
- **WHEN** 条件を満たす対局を変換する
- **THEN** 1行に、その対局の指し手が初手から順に空白区切りで並ぶ

### Requirement: 学習の入力と出力
学習器は、学習用棋譜ファイル、検証用棋譜ファイル、初期値の pp.bin、iteration 数、step 数を受け取らなければならない (SHALL)。
1 iteration は、探索を1回行い、その結果を使って更新を step 数だけ行うことである。
学習器は iteration が終わるたびに pp.bin を上書きする。書き込みの途中で止まっても、前回の pp.bin が壊れないようにする。
学習の途中で止めても、出力された pp.bin を初期値として与えれば学習を再開できる。

#### Scenario: 再開
- **WHEN** 学習を 3 iteration で止め、出力された pp.bin を初期値にしてもう一度学習器を起動する
- **THEN** 4 iteration 目に相当する学習が行われる

#### Scenario: 解析できない棋譜
- **WHEN** 学習用棋譜に、合法手として解析できない指し手を含む対局がある
- **THEN** その対局は学習に使わず、件数を表示して学習を続ける

### Requirement: Bonanza メソッドによる勾配
学習器は、学習用棋譜の各局面 p（棋譜の手を m* とする）について、`legalMoves` が返すすべての手 m（擬似合法手）を指した局面を浅く探索し、その読み筋の末端局面 leaf(m) と評価値 v(m)（p の手番側から見た値）を求めなければならない (SHALL)。
探索は1手と静止探索（駒を取る手だけ）とし、時間制限・置換表・乱数を使わない。同じ pp と局面からは常に同じ結果を返す。
棋譜の手 m* は全幅で探索し、それ以外の手は窓 [v(m*) - 256, v(m*) + 256] で探索してよい。
目的関数は次の J とし、各パラメータについて J の勾配を求める。

```
J = sum_p sum_{m != m*} T(clip(v(m) - v(m*)))
T(x) = 1 / (1 + exp(-a * x))      a = 0.0273
clip(x) = x を [-256, 256] に収めた値
```

|v(m) - v(m*)| >= 256 の手は勾配に寄与しない。
探索で得た読み筋は、その iteration の間は固定する。各 step では、固定した読み筋の末端局面をその時点の pp で評価し直して勾配を求める。

#### Scenario: 窓の外の手
- **WHEN** v(m) - v(m*) が 256 以上、または -256 以下の手がある
- **THEN** その手は勾配に寄与せず、J には T(256) または T(-256) が足される

#### Scenario: 決定的な探索
- **WHEN** 同じ pp.bin と同じ棋譜で学習器を2回起動する
- **THEN** 2回の学習結果の pp.bin は同じになる

#### Scenario: 決定的な並列化
- **WHEN** 同じ pp.bin と同じ棋譜で、スレッド数を変えて学習器を起動する
- **THEN** 学習結果の pp.bin は同じになる

#### Scenario: 候補の手が1つだけの局面
- **WHEN** `legalMoves` が返す手が棋譜の手1つだけの局面がある
- **THEN** その局面は勾配に寄与しない

### Requirement: 符号による更新
学習器は、各 step で勾配を足し終えたあと、勾配の符号を見て各パラメータを 1 ずつ動かさなければならない (SHALL)。勾配が正なら 1 減らし、負なら 1 増やし、0 なら動かさない。
値は int16 の範囲を超えないようにする。

#### Scenario: 1 step での変化
- **WHEN** step 数を 1 にして 1 iteration 学習する
- **THEN** pp.bin の各値は、学習前と比べて -1, 0, +1 のいずれかだけ変わっている

#### Scenario: 1 iteration での変化
- **WHEN** step 数を S にして 1 iteration 学習する
- **THEN** pp.bin の各値の変化の絶対値は S 以下である

### Requirement: 対称性を保つ
学習器が出力する pp.bin は、行列の対称、先後対称、左右対称を満たさなければならない (SHALL)。
左右対称は pp[a][b] == pp[mir(a)][mir(b)] である。mir は盤を左右に反転する写像で、盤上の駒は同じ駒のまま f 筋 r 段が (10 - f) 筋 r 段に移り、持ち駒は変わらない。
対称性で互いに結ばれたパラメータは1つのパラメータとして扱い、勾配を合算して更新する。符号が逆向きに自分自身へ結ばれるパラメータは 0 に固定する。

#### Scenario: 対称性の検査
- **WHEN** 対称性を満たす初期値から1 iteration 学習した pp.bin を検査する
- **THEN** すべての a, b について、行列の対称、先後対称、左右対称が成り立つ

### Requirement: 進み具合の表示
学習器は、各 iteration の終わりに、iteration 番号、学習用棋譜での J、検証用棋譜での一致率を表示しなければならない (SHALL)。
J は、その iteration の探索で求めた値（更新前の pp による値）とする。
一致率は、iteration の更新を終えた pp で検証用棋譜を探索し、v(m) が最大になる手が棋譜の手と一致した局面の割合とする。

#### Scenario: 表示
- **WHEN** 1 iteration が終わる
- **THEN** iteration 番号、J、一致率が1行で表示される
